# Accessibility (a11y)

Accessibility is not a checklist — it is a quality standard. Every component must be usable by keyboard, screen reader, and pointer users equally.

---

## Foundations

### Prefer semantic HTML

Native elements carry built-in semantics, keyboard behaviour, and ARIA roles for free. Use them before reaching for ARIA.

| Intent | Use | Not |
| --- | --- | --- |
| Clickable action | `<button>` | `<div onClick>` |
| Navigation link | `<a href>` | `<button onClick={navigate}>` |
| Page section | `<main>`, `<nav>`, `<aside>`, `<footer>` | `<div id="main">` |
| Grouped fields | `<fieldset>` + `<legend>` | `<div>` |
| Data table | `<table>`, `<th scope>`, `<caption>` | `<div>` grid |
| Toggle | `<input type="checkbox">` | custom `<div role="checkbox">` |

### ARIA — only where native semantics are insufficient

First rule of ARIA: do not use ARIA if a native HTML element or attribute does the job.

```tsx
// Bad — div with ARIA role when a button would do
<div role="button" tabIndex={0} onClick={submit}>Submit</div>

// Good — native button handles role, keyboard, focus automatically
<button type="button" onClick={submit}>Submit</button>
```

When ARIA is required, every `role` must have its required states and properties:

```tsx
// role="dialog" requires aria-labelledby or aria-label
<div role="dialog" aria-labelledby="dialog-title" aria-modal="true">
  <h2 id="dialog-title">Confirm deletion</h2>
</div>
```

## Keyboard Navigation

Every interactive element must be reachable and operable by keyboard alone.

- **Tab** — moves focus forward through interactive elements
- **Shift+Tab** — moves focus backward
- **Enter / Space** — activates buttons; Enter follows links
- **Arrow keys** — navigate within composite widgets (menus, tabs, radio groups)
- **Escape** — closes modals, dropdowns, and popovers

### Focus management

Move focus explicitly when the DOM changes significantly:

```tsx
// Move focus to dialog when it opens
useEffect(() => {
  if (isOpen) dialogRef.current?.focus();
}, [isOpen]);

// Return focus to the trigger when dialog closes
useEffect(() => {
  if (!isOpen) triggerRef.current?.focus();
}, [isOpen]);
```

### Focus trap in modals

```tsx
import { useEffect, useRef } from 'react';

const FOCUSABLE = [
  'a[href]', 'button:not([disabled])', 'input:not([disabled])',
  'select:not([disabled])', 'textarea:not([disabled])',
  '[tabindex]:not([tabindex="-1"])',
].join(', ');

export function useFocusTrap(ref: React.RefObject<HTMLElement>, active: boolean) {
  useEffect(() => {
    if (!active || !ref.current) return;
    const elements = Array.from(ref.current.querySelectorAll<HTMLElement>(FOCUSABLE));
    const first = elements[0];
    const last = elements[elements.length - 1];

    function handleKeyDown(e: KeyboardEvent) {
      if (e.key !== 'Tab') return;
      if (e.shiftKey) {
        if (document.activeElement === first) { e.preventDefault(); last.focus(); }
      } else {
        if (document.activeElement === last) { e.preventDefault(); first.focus(); }
      }
    }

    ref.current.addEventListener('keydown', handleKeyDown);
    first?.focus();
    return () => ref.current?.removeEventListener('keydown', handleKeyDown);
  }, [active, ref]);
}
```

### Visible focus styles

Never remove focus outlines without replacing them:

```css
/* Bad */
:focus { outline: none; }

/* Good — custom focus style */
:focus-visible {
  outline: 2px solid var(--color-focus-ring);
  outline-offset: 2px;
  border-radius: 4px;
}
```

Use `:focus-visible` (not `:focus`) so the ring only appears for keyboard navigation, not mouse clicks.

## Screen Readers

### Live regions

Announce dynamic content changes without moving focus:

```tsx
// Status messages — polite (waits for screen reader to finish)
<div role="status" aria-live="polite" aria-atomic="true">
  {statusMessage}
</div>

// Errors and alerts — assertive (interrupts immediately)
<div role="alert" aria-live="assertive">
  {errorMessage}
</div>
```

Keep live region elements in the DOM at all times — only change their content. Inserting and removing them can cause missed announcements.

### Hidden content

```tsx
// Visually hidden but announced by screen readers
<span className="sr-only">Loading user profile</span>

// Hidden from both visual and screen readers
<div aria-hidden="true">decorative icon</div>
```

```css
/* sr-only utility */
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
```

### Icon buttons

Icon-only buttons must have an accessible label:

```tsx
// Good
<button type="button" aria-label="Close dialog">
  <XIcon aria-hidden="true" />
</button>

// Bad — no label, screen reader announces nothing useful
<button type="button">
  <XIcon />
</button>
```

## Images

```tsx
// Informative image — describe the content
<img src={avatar} alt={`${user.name}'s avatar`} />

// Decorative image — empty alt, screen readers skip it
<img src={divider} alt="" role="presentation" />

// Complex image — short alt + long description
<img src={chart} alt="Revenue chart" aria-describedby="chart-desc" />
<p id="chart-desc">Revenue grew 42% YoY, from $1.2M to $1.7M.</p>
```

## Forms

See `references/forms.md` for full form patterns. Key rules:

- Every input has an associated `<label>` via `htmlFor` / `id` — never use `placeholder` as a label
- Required fields use `aria-required="true"` or native `required`
- Validation errors use `aria-describedby` to associate the error message with the input
- Error messages are announced via `role="alert"` or a live region

## Colour and Contrast

- Minimum contrast ratio: **4.5:1** for normal text, **3:1** for large text and UI components
- Never use colour as the only means of conveying information — pair with text, icon, or pattern
- Test with a colour blindness simulator before shipping

## Announcements for Loading

```tsx
function DataTable({ isLoading, data }: DataTableProps) {
  return (
    <>
      {/* Screen reader announcement for loading state */}
      <span role="status" aria-live="polite" className="sr-only">
        {isLoading ? 'Loading data, please wait.' : 'Data loaded.'}
      </span>
      {isLoading ? <TableSkeleton /> : <Table data={data} />}
    </>
  );
}
```
