# Internationalisation (i18n)

Internationalisation must be designed in from the start — retrofitting it onto a finished UI is expensive. Every user-visible string, date, number, and currency must go through the i18n layer.

---

## Checklist Before Shipping

- [ ] No hardcoded user-visible strings in component files
- [ ] All dates, times, and numbers use `Intl` formatters or library equivalents
- [ ] Plural forms handled — never `count + ' items'`
- [ ] RTL layout verified for Arabic, Hebrew, Persian, Urdu
- [ ] Locale detected from browser preference, not hardcoded
- [ ] Locale persisted in URL, cookie, or user profile — not only in memory

---

## Choosing a Library

| Framework | Preferred library |
| --- | --- |
| Next.js App Router | `next-intl` |
| Next.js Pages Router | `next-i18next` or `next-intl` |
| Vite + React | `react-i18next` |

## next-intl (Next.js App Router)

### Project structure

```
messages/
  en.json
  fr.json
  ar.json
middleware.ts
next.config.ts
app/
  [locale]/
    layout.tsx
    page.tsx
```

### Configuration

```ts
// next.config.ts
import createNextIntlPlugin from 'next-intl/plugin';
const withNextIntl = createNextIntlPlugin();
export default withNextIntl({ /* next config */ });

// middleware.ts
import createMiddleware from 'next-intl/middleware';
export default createMiddleware({
  locales: ['en', 'fr', 'ar'],
  defaultLocale: 'en',
  localePrefix: 'always', // /en/... /fr/... /ar/...
});
export const config = { matcher: ['/((?!api|_next|.*\\..*).*)'] };
```

### Message files

```json
// messages/en.json
{
  "nav": {
    "home": "Home",
    "products": "Products",
    "cart": "Cart ({count, plural, =0 {empty} one {# item} other {# items}})"
  },
  "product": {
    "addToCart": "Add to cart",
    "price": "{price, number, ::currency/USD}",
    "inStock": "{count, plural, one {# item left} other {# items left}}"
  },
  "errors": {
    "required": "This field is required",
    "notFound": "{resource} not found"
  }
}
```

### Using translations

```tsx
// app/[locale]/layout.tsx
import { NextIntlClientProvider } from 'next-intl';
import { getMessages } from 'next-intl/server';

export default async function LocaleLayout({
  children,
  params: { locale },
}: {
  children: React.ReactNode;
  params: { locale: string };
}) {
  const messages = await getMessages();
  return (
    <html lang={locale} dir={locale === 'ar' ? 'rtl' : 'ltr'}>
      <body>
        <NextIntlClientProvider messages={messages}>
          {children}
        </NextIntlClientProvider>
      </body>
    </html>
  );
}

// Server component
import { getTranslations } from 'next-intl/server';

export default async function ProductPage() {
  const t = await getTranslations('product');
  return <h1>{t('addToCart')}</h1>;
}

// Client component
'use client';
import { useTranslations } from 'next-intl';

export function CartButton({ count }: { count: number }) {
  const t = useTranslations('nav');
  return <button>{t('cart', { count })}</button>;
}
```

## react-i18next (Vite + React)

```ts
// lib/i18n.ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';
import Backend from 'i18next-http-backend';

i18n
  .use(Backend)           // load translations from /public/locales
  .use(LanguageDetector)  // detect from browser, localStorage, querystring
  .use(initReactI18next)
  .init({
    fallbackLng: 'en',
    ns: ['common', 'product', 'errors'],
    defaultNS: 'common',
    interpolation: { escapeValue: false }, // React escapes by default
    detection: {
      order: ['querystring', 'localStorage', 'navigator'],
      caches: ['localStorage'],
    },
  });

export default i18n;
```

```tsx
// Usage
import { useTranslation, Trans } from 'react-i18next';

export function ProductCard({ product, count }: ProductCardProps) {
  const { t } = useTranslation('product');

  return (
    <article>
      <h2>{product.name}</h2>
      {/* Rich text with components */}
      <p>
        <Trans i18nKey="product:inStock" count={count}>
          <strong>{{ count }}</strong> items left
        </Trans>
      </p>
      <span>{t('price', { price: product.price })}</span>
    </article>
  );
}
```

## Formatting with Intl

Always use `Intl` APIs for locale-aware formatting — never construct strings manually.

```ts
// lib/format.ts

// Numbers
export function formatNumber(value: number, locale: string, options?: Intl.NumberFormatOptions): string {
  return new Intl.NumberFormat(locale, options).format(value);
}

// Currency
export function formatCurrency(amount: number, locale: string, currency: string): string {
  return new Intl.NumberFormat(locale, { style: 'currency', currency }).format(amount);
}

// Date
export function formatDate(date: Date | string, locale: string, options?: Intl.DateTimeFormatOptions): string {
  return new Intl.DateTimeFormat(locale, options).format(new Date(date));
}

// Relative time (e.g. "3 days ago")
export function formatRelativeTime(date: Date, locale: string): string {
  const diff = (date.getTime() - Date.now()) / 1000;
  const rtf = new Intl.RelativeTimeFormat(locale, { numeric: 'auto' });
  const units: [Intl.RelativeTimeFormatUnit, number][] = [
    ['year', 31536000], ['month', 2592000], ['week', 604800],
    ['day', 86400], ['hour', 3600], ['minute', 60], ['second', 1],
  ];
  for (const [unit, seconds] of units) {
    if (Math.abs(diff) >= seconds) return rtf.format(Math.round(diff / seconds), unit);
  }
  return rtf.format(0, 'second');
}

// List (e.g. "Alice, Bob, and Carol")
export function formatList(items: string[], locale: string): string {
  return new Intl.ListFormat(locale, { style: 'long', type: 'conjunction' }).format(items);
}
```

## Plurals

Never concatenate count with a string:

```ts
// Bad
`${count} item${count !== 1 ? 's' : ''}` // breaks for many languages

// Good — ICU plural syntax in message files
// en.json: "items": "{count, plural, =0 {No items} one {# item} other {# items}}"
t('items', { count })
```

Languages have up to 6 plural forms (zero, one, two, few, many, other). ICU format handles all of them automatically when translations are provided correctly.

## RTL Layout

Set `dir` on `<html>` based on locale. Never hardcode `dir="ltr"`.

```tsx
const RTL_LOCALES = ['ar', 'he', 'fa', 'ur'];
const dir = RTL_LOCALES.includes(locale) ? 'rtl' : 'ltr';
<html lang={locale} dir={dir}>
```

### CSS for RTL

Use logical properties — they flip automatically with `dir`:

```css
/* Good — logical properties, work in both LTR and RTL */
.card {
  margin-inline-start: 1rem;   /* left in LTR, right in RTL */
  padding-inline: 1.5rem;
  border-inline-start: 2px solid var(--color-brand);
  text-align: start;
}

/* Bad — physical properties, break in RTL */
.card {
  margin-left: 1rem;
  padding-left: 1.5rem;
  border-left: 2px solid var(--color-brand);
  text-align: left;
}
```

Tailwind supports RTL with the `rtl:` variant:

```tsx
<div className="ml-4 rtl:ml-0 rtl:mr-4">
```

Or enable logical properties plugin:

```tsx
// With @tailwindcss/typography or custom config
<div className="ms-4">  {/* margin-inline-start */}
```

## Locale Detection and Persistence

Detect from browser, persist in URL or cookie — never only in memory:

```ts
// Priority order for locale detection
// 1. URL segment (/fr/products) — source of truth, shareable
// 2. Cookie (locale=fr) — persists across sessions
// 3. Accept-Language header (server) — browser preference
// 4. navigator.language (client fallback)
// 5. Default locale

// Locale switcher — update URL and cookie
function setLocale(locale: string) {
  document.cookie = `locale=${locale}; path=/; max-age=${60 * 60 * 24 * 365}`;
  // Navigate to the new locale URL
  router.push(`/${locale}${currentPath}`);
}
```

## Translation File Conventions

```json
// Flat keys for small namespaces
{ "save": "Save", "cancel": "Cancel" }

// Nested keys for large namespaces
{
  "product": {
    "title": "Product",
    "actions": {
      "addToCart": "Add to cart",
      "removeFromCart": "Remove from cart"
    }
  }
}
```

- One JSON file per locale per namespace — `en/product.json`, `fr/product.json`
- Keys in `camelCase` — match the JS variable convention
- Never use the English string as the key — use semantic keys (`product.addToCart`, not `Add to cart`)
- Keep keys stable — changing a key breaks translations that reference it

## Missing Translations

Always provide a fallback locale. Log missing keys in development — never silently show the key:

```ts
i18n.init({
  fallbackLng: 'en',
  saveMissing: true,           // development only
  missingKeyHandler: (locale, ns, key) => {
    if (process.env.NODE_ENV === 'development') {
      console.warn(`Missing translation: ${locale}/${ns}/${key}`);
    }
  },
});
```
