# Internationalisation (i18n)

Internationalisation must be designed in from the start — retrofitting it onto a finished UI is expensive. Every user-visible string, date, number, and currency must go through the i18n layer. For framework-specific implementations, fetch current docs via Context7.

---

## Checklist Before Shipping

- [ ] No hardcoded user-visible strings in component files
- [ ] All dates, times, and numbers use `Intl` formatters or library equivalents
- [ ] Plural forms handled via ICU syntax — never `count + ' items'`
- [ ] RTL layout verified for Arabic, Hebrew, Persian, Urdu
- [ ] Locale detected from browser preference, not hardcoded
- [ ] Locale persisted in URL, cookie, or user profile — not only in memory

## Translation File Conventions

```json
// messages/en.json — one file per locale per namespace

// Flat keys for small namespaces
{ "save": "Save", "cancel": "Cancel" }

// Nested keys for large namespaces
{
  "product": {
    "title": "Product",
    "actions": {
      "addToCart": "Add to cart",
      "removeFromCart": "Remove from cart"
    }
  }
}
```

Rules:

- One JSON file per locale per namespace — `en/product.json`, `fr/product.json`
- Keys in `camelCase` — matches JS variable convention
- Never use the English string as the key — use semantic keys (`product.addToCart`, not `Add to cart`)
- Keep keys stable — changing a key breaks all translations that reference it
- Never hardcode UI copy in component files — always reference a translation key

## ICU Message Format

Use ICU syntax for all messages that contain variables, plurals, or conditionals:

```json
{
  "cart":    "Cart ({count, plural, =0 {empty} one {# item} other {# items}})",
  "price":   "{price, number, ::currency/USD}",
  "inStock": "{count, plural, one {# item left} other {# items left}}",
  "welcome": "Welcome back, {name}!"
}
```

### Plurals

Never concatenate count with a string — it breaks for languages with more than two plural forms:

```ts
// Bad — only works in English
`${count} item${count !== 1 ? 's' : ''}`

// Good — ICU plural handles all 6 forms: zero, one, two, few, many, other
t('items', { count })
```

Languages have up to 6 plural forms. ICU handles all of them automatically when translations are provided correctly.

## Formatting with Intl

Always use native `Intl` APIs for locale-aware formatting — never construct date, number, or currency strings manually. These work in all frameworks with no library dependency.

```ts
// lib/format.ts — framework-agnostic

// Numbers
export function formatNumber(value: number, locale: string, options?: Intl.NumberFormatOptions): string {
  return new Intl.NumberFormat(locale, options).format(value);
}

// Currency
export function formatCurrency(amount: number, locale: string, currency: string): string {
  return new Intl.NumberFormat(locale, { style: 'currency', currency }).format(amount);
}

// Date
export function formatDate(date: Date | string, locale: string, options?: Intl.DateTimeFormatOptions): string {
  return new Intl.DateTimeFormat(locale, options).format(new Date(date));
}

// Relative time — "3 days ago", "in 2 hours"
export function formatRelativeTime(date: Date, locale: string): string {
  const diff = (date.getTime() - Date.now()) / 1000;
  const rtf = new Intl.RelativeTimeFormat(locale, { numeric: 'auto' });
  const units: [Intl.RelativeTimeFormatUnit, number][] = [
    ['year', 31536000], ['month', 2592000], ['week', 604800],
    ['day', 86400], ['hour', 3600], ['minute', 60], ['second', 1],
  ];
  for (const [unit, seconds] of units) {
    if (Math.abs(diff) >= seconds) return rtf.format(Math.round(diff / seconds), unit);
  }
  return rtf.format(0, 'second');
}

// List — "Alice, Bob, and Carol"
export function formatList(items: string[], locale: string): string {
  return new Intl.ListFormat(locale, { style: 'long', type: 'conjunction' }).format(items);
}
```

## RTL Layout

Set `dir` on `<html>` based on locale — never hardcode `dir="ltr"`:

```ts
const RTL_LOCALES = ['ar', 'he', 'fa', 'ur'];

function getDir(locale: string): 'ltr' | 'rtl' {
  return RTL_LOCALES.includes(locale) ? 'rtl' : 'ltr';
}

// Apply on locale change — framework-specific wiring in the adapter
document.documentElement.setAttribute('lang', locale);
document.documentElement.setAttribute('dir', getDir(locale));
```

### CSS for RTL

Use logical properties — they flip automatically with `dir`. See `references/styling.md` for the full logical properties reference.

```css
/* Good — logical, works in both LTR and RTL */
.card {
  margin-inline-start: 1rem;
  padding-inline: 1.5rem;
  border-inline-start: 2px solid var(--color-brand);
  text-align: start;
}

/* Bad — physical, breaks in RTL */
.card {
  margin-left: 1rem;
  padding-left: 1.5rem;
  border-left: 2px solid var(--color-brand);
  text-align: left;
}
```

## Locale Detection and Persistence

Detect from browser, persist in URL or cookie — never only in memory:

```
Priority order for locale detection:
  1. URL segment (/fr/products)     — source of truth, shareable, SSR-readable
  2. Cookie (locale=fr)             — persists across sessions, SSR-readable
  3. Accept-Language header (server) — browser preference at request time
  4. navigator.language (client)    — fallback when no server context
  5. Default locale                 — last resort
```

```ts
// Framework-agnostic locale switcher
function setLocale(locale: string, currentPath: string): void {
  // Persist in cookie (SSR-readable)
  document.cookie = `locale=${locale}; path=/; max-age=${60 * 60 * 24 * 365}; SameSite=Lax`;
  // Navigate to localised URL — framework router wiring in adapter
  window.location.href = `/${locale}${currentPath}`;
}
```

## Missing Translations

Always provide a fallback locale. Log missing keys in development — never silently display the raw key to the user:

```
Required behaviour:
  Missing key in current locale  → render fallback locale string
  Missing key in fallback locale → log a warning in development; render key as last resort
  Production                     → never log; silently fall back
```

Configure your i18n library with `fallbackLng: 'en'` and a `missingKeyHandler` that logs only in development.  Fetch framework-specific docs via Context7.
