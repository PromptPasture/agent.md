# ZONE-FORMAT.md

Each zone gets its own self-contained HTML file under `zones/`. It should be readable standalone — someone opening it should understand the zone without needing the master plan.

---

## What to Include

- **Header**
  - Zone name and one-line purpose
  - Key dimensions or area (if known)
  - Sun exposure and microclimate notes
- **Design Intent**
  - What this zone should feel like and how it will be used
  - Relationship to adjacent zones (e.g. transition from patio to lawn)
- **Layout Notes**
  - Rough spatial organisation in plain language — no technical drawing needed
  - Key structural elements: paths, edges, raised beds, seating, screens, etc.
  - If a photo or site plan was shared, reference relevant features visible in it
- **Planting Approach**
  - General character of planting (e.g. low groundcover, mixed border, statement tree)
  - Any specific requirements: non-toxic, drought-tolerant, low-maintenance, edible
  - Do not list specific cultivars unless the user requested them — keep it general
- **Considerations**
  - Challenges specific to this zone: drainage, shade, wind, visibility, soil
  - Any constraints: existing features to work around, budget limits for this zone
- **Phase Reference**
  - Which phase(s) address this zone

---

## HTML Structure Guidelines

- Clean, readable layout — this is a reference document, not a design portfolio
- Use a simple colour scheme; avoid heavy styling
- Include a clear zone name heading at the top
- Sections map to the headings above
- Add a footer with last-updated date and link back to `../PLAN.md`
