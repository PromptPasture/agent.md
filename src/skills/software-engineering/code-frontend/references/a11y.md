# Accessibility (a11y)

Accessibility is a quality standard, not a checklist. Every component must work for keyboard, screen reader, and pointer users.

---

## Foundations

### Prefer semantic HTML

Native elements carry built-in semantics, keyboard behaviour, and ARIA roles for free. Use them before reaching for ARIA.

|Intent|Use|Not|
|---|---|---|
|Clickable action|`<button>`|`<div>` with a click handler|
|Navigation link|`<a href>`|`<button>` with a router call|
|Page section|`<main>`, `<nav>`, `<aside>`, `<footer>`|`<div id="main">`|
|Grouped fields|`<fieldset>` + `<legend>`|`<div>`|
|Data table|`<table>`, `<th scope>`, `<caption>`|`<div>` grid|
|Toggle|`<input type="checkbox">`|custom `<div role="checkbox">`|

### ARIA — only where native semantics are insufficient

First rule of ARIA: do not use ARIA if a native HTML element or attribute does the job.

```html
<!-- Bad — div with ARIA role when a button would do -->
<div role="button" tabindex="0">Submit</div>

<!-- Good — native button handles role, keyboard, focus automatically -->
<button type="button">Submit</button>
```

When ARIA is required, every `role` must have its required states and properties:

```html
<!-- role="dialog" requires aria-labelledby or aria-label -->
<div role="dialog" aria-labelledby="dialog-title" aria-modal="true">
  <h2 id="dialog-title">Confirm deletion</h2>
</div>
```

## Keyboard Navigation

Every interactive element must be reachable and operable by keyboard alone.

- **Tab**: moves focus forward through interactive elements
- **Shift+Tab**: moves focus backward
- **Enter / Space**: activates buttons; Enter follows links
- **Arrow keys**: navigate within composite widgets (menus, tabs, radio groups)
- **Escape**: closes modals, dropdowns, and popovers

### Focus management

Move focus explicitly when the DOM changes significantly:

- When a modal or dialog opens → move focus to the first interactive element inside it
- When a modal or dialog closes → return focus to the element that triggered it
- When a route changes → move focus to the page heading or main content area
- When inline content expands (accordion, disclosure) → no focus move needed unless content contains an error

### Focus trap in modals

When a modal is open, Tab and Shift+Tab must cycle only within the modal — never escape to the page behind it.

**Algorithm:**

1. Query all focusable elements inside the modal container
2. On Tab: if focus is on the last element, move it to the first
3. On Shift+Tab: if focus is on the first element, move it to the last
4. On Escape: close the modal and return focus to the trigger

Focusable selector:

```
a[href], button:not([disabled]), input:not([disabled]),
select:not([disabled]), textarea:not([disabled]),
[tabindex]:not([tabindex="-1"])
```

### Visible focus styles

Never remove focus outlines without replacing them:

```css
/* Bad */
:focus { outline: none; }

/* Good — custom focus style */
:focus-visible {
  outline: 2px solid var(--color-focus-ring);
  outline-offset: 2px;
  border-radius: 4px;
}
```

Use `:focus-visible` (not `:focus`) so the ring appears only for keyboard navigation, not mouse clicks.

## Screen Readers

### Live regions

Announce dynamic content changes without moving focus:

```html
<!-- Status messages — polite (waits for screen reader to finish) -->
<div role="status" aria-live="polite" aria-atomic="true">
  <!-- Update text content here; do not insert/remove the element -->
</div>

<!-- Errors and alerts — assertive (interrupts immediately) -->
<div role="alert" aria-live="assertive">
  <!-- Update text content here -->
</div>
```

**Critical rule:** keep live region elements in the DOM at all times — only change their text content. Inserting or removing the element itself causes missed announcements in most screen readers.

### Visually hidden content

```html
<!-- Visible to screen readers, hidden visually -->
<span class="sr-only">Loading user profile</span>

<!-- Hidden from both screen readers and visual users -->
<div aria-hidden="true"><!-- decorative icon --></div>
```

```css
/* sr-only utility — works in all frameworks */
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
```

### Icon buttons

Icon-only buttons must have an accessible label:

```html
<!-- Good -->
<button type="button" aria-label="Close dialog">
  <!-- icon, aria-hidden="true" -->
</button>

<!-- Bad — screen reader announces nothing useful -->
<button type="button">
  <!-- icon with no label -->
</button>
```

### Loading announcements

Announce loading state changes without moving focus:

```html
<!-- Always present in DOM; only the text content changes -->
<span role="status" aria-live="polite" class="sr-only">
  <!-- "Loading data, please wait." while loading -->
  <!-- "Data loaded." when complete -->
</span>
```

## Images

```html
<!-- Informative — describe the content -->
<img src="avatar.jpg" alt="Jane Smith's profile photo" />

<!-- Decorative — empty alt, screen readers skip it -->
<img src="divider.svg" alt="" role="presentation" />

<!-- Complex — short alt + long description -->
<img src="chart.png" alt="Revenue chart" aria-describedby="chart-desc" />
<p id="chart-desc">Revenue grew 42% YoY, from $1.2M to $1.7M.</p>
```

## Forms

See `references/forms.md` for full form patterns. Key rules:

- Every input has an associated `<label>` via matching `for` / `id` — never use `placeholder` as a label
- Required fields use `aria-required="true"` or native `required`
- Invalid fields use `aria-invalid="true"` and `aria-describedby` pointing to the error message
- Error messages are announced via `role="alert"` or a live region

## Colour and Contrast

- Minimum contrast ratio: **4.5:1** for normal text, **3:1** for large text and UI components
- Never use colour as the only means of conveying information — pair with text, icon, or pattern
- Test with a colour blindness simulator before shipping
