# Documentation skills

These skills are in progress under `src/skills/in-progress/`. Not yet published or included in release archives.

## Skills

### `write-api-docs`

Write or revise reference documentation for existing APIs — REST endpoints, GraphQL operations, gRPC methods, WebSocket messages, authentication, parameters, schemas, responses, errors, limits, and executable request examples.

### `write-changelog`

Write or revise developer-facing changelogs: `CHANGELOG.md` files, unreleased sections, version entries, commit/PR categorization, breaking changes, deprecations, removals, fixes, and security changes.

### `write-readme`

Write or revise project README files: repository, library, CLI, service, internal-tool, and open-source introductions, installation, quick start, usage, configuration, development, contribution, support, and license guidance.

### `write-release-notes`

Write or revise user-facing release notes: product updates, version announcements, what's-new summaries, app-store notes, improvements, fixes, known issues, upgrade guidance, and action-required notices.

### `write-runbook`

Write or revise executable operational runbooks: routine maintenance, deployment, recovery, secret rotation, diagnostics, alert response, on-call triage, mitigation, verification, rollback, communication, and escalation procedures.

### `write-ticket`

Write or revise Jira/GitHub/Linear tickets — bug, feature, task, chore, documentation, and spike. Uses type-specific writing models; tracker adaptation changes field placement, not prose style. Does not force user-story framing onto non-story work. See [Product skills](/docs/skills/product.md) for routing rules.

### `manage`

Coordinate active work across people, agents, tasks, dependencies, blockers, and handoffs. Maintains an execution view with goals, owners, status, blockers, and next actions.

### `design-api`

API design guidance.

### `markitdown`

Convert one local document at a time (PDF, Word, PowerPoint, Excel, EPUB, Outlook) to Markdown using the `markitdown` CLI. Default output is a temporary file for model consumption; session-local reuse when source is unchanged (same path, size, mtime). Requires explicit user approval before installing missing dependencies. No wrapper scripts.
